# B-96: blank face tile in "Is this ...?"

## The bug (from Waleed's screenshots)

- Desktop app, Faces > "Is this ...?": the suggestion tile sometimes shows a
  blank white picture instead of the cropped face.
- In the class photo next to it, the face is marked only by a thin box that is
  hard to see.
- Logged as B-96 by the release thread and first in line for 0.12.

## Where it stands

- Fix is on branch `fix/b96-blank-face-tile` (commit db4e538), based on
  `claude/project-thread-dmb0um` (b57e3a0), the newest branch with the face
  work. `main` is behind, so review against that branch, not `main`.
- Root cause: the face picture and the class photo beside it were made by
  different code. When the original photo could not be reached and its big
  copy did not exist, the class photo fell back to the small copy but the face
  picture returned nothing, so the screen showed a white square. Two related
  faults: a question about a face that no longer exists got no picture, and
  face pictures were stored under the face's number for ever, so a new face
  could show an old face's picture.
- Changed: `desktop/src/core/engine.ts` (cut from the small copy when the
  original is unreachable; stored picture name includes photo and box),
  `desktop/src/renderer/views/faces.js` (grey while loading, plain figure if no
  picture, skip faces that no longer exist), `desktop/src/renderer/styles.css`
  (thick blue ring with a white edge around the asked-about face, rest dimmed).
- Tests added: `desktop/src/core/face-crop.test.ts` (4 unit tests) and
  `desktop/e2e/face-tile.spec.ts` (robot test, Arabic/RTL). The new tests
  failed before the fix.
- Passed: `npm test` 67/67, `tsc --noEmit` clean, robot tests face-tile,
  face-flaws, accessibility (en, ar, dark), books, every-tab (en, ar) under xvfb.
- NOT run: the rest of the robot suite (including faces-real) and anything on a
  real Mac or Windows machine. The release thread should run the full suite
  before merging.
- Known, left as is: a face picture waits behind background face-finding, so on
  a busy library the tile can stay grey for a few seconds. Old files in the
  app's `cache/faces` folder are no longer used and are harmless.
